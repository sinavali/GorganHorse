# Docs Navigation

## Index First
Always start with `docs/INDEX.md`. It contains a section-by-section map
of the documentation. Use it to locate the 1-3 files relevant to the task.

## Reading Rules
- Read the smallest possible set of files.
- Prefer section headings and the first paragraph of each section.
- If a file exceeds 500 lines, read it in chunks. Do not paste the entire
  file into context.
- After reading, extract only: Objective, Constraints, Interfaces, Edge Cases.

## What Not To Do
- Do not `cat` the entire `/docs` directory.
- Do not read files "just in case."
- Do not copy documentation text into your response. Summarize it.
- Do not invent product behavior. If it is not in the docs, say so.
